# 网关 Sentinel 规则参数说明

规则从 Nacos 热加载，命名空间与网关配置相同，分组 `DEFAULT_GROUP`，格式 JSON。

| Data ID | 本地文件 | 规则类型 |
|---|---|---|
| `mall-gateway-gw-api.json` | `mall-gateway-gw-api.json` | API 分组 |
| `mall-gateway-gw-flow.json` | `mall-gateway-gw-flow.json` | 网关流控 |
| `mall-gateway-degrade.json` | `mall-gateway-degrade.json` | 熔断降级 |

请求先按 API 分组匹配路径，再按分组名套用流控和熔断。`gw-flow.json` 的 `resource`、`degrade.json` 的 `resource` 必须与 `gw-api.json` 的 `apiName` 同名。`resourceMode` 为 `1` 时，`resource` 是分组名，不是 URL。

---

## 1. API 分组（`mall-gateway-gw-api.json`）

把若干路径归到同一个资源名。流控、熔断都按这个名字计数。

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `apiName` | string | 是 | 分组名。流控、熔断的 `resource` 填这个值。 |
| `predicateItems` | array | 是 | 路径匹配项，命中任意一项即归入该分组。 |
| `predicateItems[].pattern` | string | 是 | 匹配路径。前缀匹配时写到目录为止，例如 `/sys/`，不要写 `/sys/**`。 |
| `predicateItems[].matchStrategy` | int | 是 | `0` 精确匹配；`1` 前缀匹配；`2` 正则匹配。 |

当前示例：

- `/sys/dictionary/page`：精确匹配该接口。
- `mall-sys`：前缀 `/sys/`，覆盖该前缀下全部接口。

一条请求可以同时命中多个分组。例如 `/sys/dictionary/page` 会进入上面两组，两组规则各自独立生效，任一触发都会拒绝。

---

## 2. 网关流控（`mall-gateway-gw-flow.json`）

限制某个 API 分组在统计窗口内的请求数。超限返回 HTTP 429，响应体由 `spring.cloud.sentinel.scg.fallback` 决定。

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `resource` | string | 是 | 资源名。`resourceMode=1` 时填 API 分组的 `apiName`。 |
| `resourceMode` | int | 是 | `0` 按路由 ID；`1` 按自定义 API 分组。当前一律用 `1`。 |
| `grade` | int | 否 | `1` QPS（默认）；`0` 并发线程数。网关限流用 `1`。 |
| `count` | number | 是 | 窗口内允许通过的请求数。 |
| `intervalSec` | int | 否 | 统计窗口，单位秒，默认 `1`。 |
| `controlBehavior` | int | 否 | `0` 直接拒绝（默认）；`2` 匀速排队。网关场景用 `0`。 |
| `burst` | int | 否 | 突发额外请求数，仅 `controlBehavior=0` 时有效。`0` 表示不允许突发。 |
| `maxQueueingTimeoutMs` | int | 否 | 匀速排队最长等待毫秒。仅 `controlBehavior=2` 时有效。 |
| `interval` / `intervalUnit` | — | 否 | 部分控制台导出字段，与 `intervalSec` 等价，配置时只写 `intervalSec` 即可。 |
| `paramItem` | object | 否 | 按请求参数、Header、IP 等做热点限流。不配则整组共享一个计数器。 |

当前示例：

- `/sys/dictionary/page`：每秒 5 次。
- `mall-sys`：`/sys/` 前缀合计每秒 10 次。

---

## 3. 熔断降级（`mall-gateway-degrade.json`）

按调用质量打开熔断。熔断期间该资源的请求直接拒绝，不再转发下游。时长由 `timeWindow` 决定。

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `resource` | string | 是 | 资源名，填 API 分组的 `apiName`。 |
| `grade` | int | 是 | `0` 慢调用比例；`1` 异常比例；`2` 异常数。 |
| `count` | number | 是 | 随 `grade` 含义不同：`0` 时为慢调用耗时门槛（毫秒）；`1` 时为异常比例（0～1）；`2` 时为异常次数。 |
| `slowRatioThreshold` | number | `grade=0` 时必填 | 慢调用比例门槛，0～1。慢调用次数 ÷ 总次数达到该值则熔断。 |
| `minRequestAmount` | int | 否 | 统计窗口内最少请求数，默认 `5`。不足则不熔断，避免样本过少误判。 |
| `statIntervalMs` | int | 否 | 统计窗口，单位毫秒，默认 `1000`。 |
| `timeWindow` | int | 是 | 熔断持续秒数。打开后该时长内请求直接被拒绝。 |

当前示例（慢调用比例）：

- 作用在 `mall-sys`（`/sys/`）。
- 响应超过 500 毫秒记为慢调用。
- 最近 1 秒内至少 5 次请求，且慢调用达到 50%，熔断 10 秒。

三种 `grade` 对照：

| grade | 策略 | `count` 含义 | 还需配置 |
|---|---|---|---|
| `0` | 慢调用比例 | 慢调用耗时门槛（毫秒） | `slowRatioThreshold` |
| `1` | 异常比例 | 异常比例（如 `0.5` 表示 50%） | 无 |
| `2` | 异常数 | 窗口内异常次数 | 无 |

---

## 4. 新增规则时注意

1. 先在 `mall-gateway-gw-api.json` 增加分组，再在流控或熔断里用同一个 `apiName`。
2. 只改阈值时改 `gw-flow.json` 的 `count` / `intervalSec`，或 `degrade.json` 的对应字段。
3. JSON 格式错误时本次变更不生效，网关继续使用上一份成功加载的规则。
4. 控制台里看网关规则，用「API 管理」「网关流控规则」「熔断规则」，不要用普通应用的「流控规则」。
