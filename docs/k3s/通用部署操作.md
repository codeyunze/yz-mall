# k3s 部署组件与 Spring Cloud 微服务（新手操作手册）

本文面向**第一次**在 yz-mall 环境里往 k3s 上部署服务的同学：按章节顺序做，可以独立完成「从建目录 → 写配置 → 部署 → 验证」全流程。

> 命令在 **k3s 节点**上执行时，把 `kubectl` 换成 `sudo k3s kubectl`。  
> 更多排障命令见 [常用命令.md](./常用命令.md)。RustFS 专项见 [部署RustFS.md](./部署RustFS.md)。

---

## 0. 先搞清楚：配置到底加在哪？

部署一个服务时，常见有 **4 类配置**，不要混在一个文件里：

| 你要配什么 | 加在哪里 | 仓库里对应目录/文件 | 谁读取 |
|---|---|---|---|
| 镜像地址、副本数、端口、探针、CPU/内存 | **K8s YAML**（Deployment/Service） | `docs/k3s/apps/<服务名>/` | kubelet / API Server |
| 连 Nacos 的地址、密码（启动前就要有） | **Deployment 的 `env`** + **Secret** | `docs/k3s/apps/<服务名>/secret.yaml`（不入库明文）或节点上 `kubectl create secret` | Spring `bootstrap.yaml` 里的 `${NACOS_HOST}` |
| Redis、MySQL、MQ 等中间件连接串 | **Nacos 控制台** 的 `middleware.yaml` 等 | 源码里只有引用：`mall-*/**/bootstrap.yaml` | 应用启动后从 Nacos 拉 |
| 业务开关、线程池、网关路由等业务参数 | **Nacos** 各服务 Data ID | 样例在 `docs/nacos/`、`docs/example/` | 应用 + `refresh: true` 可热更新 |
| 中间件自己的 `redis.conf`、`application.properties` | **ConfigMap**（由文件生成） | `docs/k3s/apps/<服务名>/config/` | 中间件容器挂载 |

**不要做的事：**

- 不要把数据库密码、Nacos 密码写进 Git 里的 YAML
- 不要把 `127.0.0.1`、旧局域网 IP 写进 Nacos 中间件地址（上 k3s 后用 **Service DNS**）
- 不要给每个 Java 微服务都开 NodePort；**只对外暴露 gateway**

## 1. 仓库目录怎么建（第一次部署前做一次）

在 yz-mall 仓库里，建议所有 k3s 清单放在：

```text
yz-mall/docs/k3s/
├── README.md                 # 文档索引
├── 常用命令.md
├── 通用部署操作.md           # 本文
├── 部署RustFS.md
├── 中间件迁移方案.md
└── apps/                     # ★ 所有服务的 K8s 清单放这里
    ├── mall-middleware/      # 中间件命名空间相关（可选汇总）
    │   └── redis/            # 示例：Redis
    │       ├── namespace.yaml
    │       ├── secret.yaml.example
    │       ├── config/
    │       │   └── redis.conf
    │       ├── deployment.yaml
    │       ├── service.yaml
    │       └── kustomization.yaml   # 可选
    └── mall/                   # 业务微服务命名空间相关
        └── mall-sys/
            ├── namespace.yaml
            ├── secret.yaml.example
            ├── deployment.yaml
            ├── service.yaml
            └── ingress-gateway.yaml   # 仅 gateway 需要
```

**操作（在开发机仓库根目录）：**

```bash
cd yz-mall/docs/k3s
mkdir -p apps/mall-middleware/redis/config
mkdir -p apps/mall/mall-sys
```

以后每新增一个服务，就在 `apps/` 下复制一份同结构目录，改服务名即可。

## 2. 命名空间规划（先创建，再部署服务）

| 命名空间 | 放什么 |
|---|---|
| `mall-middleware` | Redis、Nacos、RocketMQ、Kafka 等 |
| `mall` | mall-gateway、mall-sys、mall-oms、mall-pms、mall-tw-* |
| `mall-monitor` | Prometheus、Grafana（可选） |
| `rustfs` | RustFS（已单独部署可保持不动） |

**步骤 2.1** 新建命名空间文件 `docs/k3s/apps/mall/namespace.yaml`：

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: mall
  labels:
    app.kubernetes.io/part-of: yz-mall
```

中间件同理，把 `name` 改成 `mall-middleware`。

**步骤 2.2** 在 k3s 节点应用：

```bash
sudo k3s kubectl apply -f docs/k3s/apps/mall/namespace.yaml
sudo k3s kubectl get ns | grep mall
```

期望看到 `mall`、`mall-middleware` 状态为 `Active`。

## 3. 镜像仓库凭证（每个命名空间做一次）

私有 ACR 镜像需要 `imagePullSecrets`，否则 Pod 会 `ImagePullBackOff`。

**步骤 3.1** 在节点上执行（密码用环境变量，不要写进文档/Git）：

```bash
export ACR_USER="你的ACR用户名"
export ACR_PASSWORD="你的ACR密码"

sudo k3s kubectl -n mall create secret docker-registry acr-gz \
  --docker-server=registry.cn-guangzhou.aliyuncs.com \
  --docker-username="$ACR_USER" \
  --docker-password="$ACR_PASSWORD" \
  --dry-run=client -o yaml | sudo k3s kubectl apply -f -

sudo k3s kubectl -n mall-middleware create secret docker-registry acr-gz \
  --docker-server=registry.cn-guangzhou.aliyuncs.com \
  --docker-username="$ACR_USER" \
  --docker-password="$ACR_PASSWORD" \
  --dry-run=client -o yaml | sudo k3s kubectl apply -f -
```

**步骤 3.2** 验证：

```bash
sudo k3s kubectl -n mall get secret acr-gz
```

**步骤 3.3** 每个 Deployment 的 `spec.template.spec` 里要有：

```yaml
imagePullSecrets:
  - name: acr-gz
```

## 4. 教程 A：部署一个中间件（以 Redis 为例）

目标：在 `mall-middleware` 命名空间跑 Redis，集群内地址  
`redis.mall-middleware.svc.cluster.local:6379`。

### 4.1 准备镜像

镜像已在 ACR：`registry.cn-guangzhou.aliyuncs.com/devyunze/redis:7.4.5`（与 `docs/docker/docker-compose.yml` 一致）。

节点上可选预拉：

```bash
sudo k3s crictl pull registry.cn-guangzhou.aliyuncs.com/devyunze/redis:7.4.5
```

### 4.2 在仓库里写配置文件

**目录：** `docs/k3s/apps/mall-middleware/redis/`

每个文件只维护一处，避免同一份配置写两遍。

| 文件 | 作用 | 是否提交 Git |
|---|---|---|
| `config/redis.conf` | Redis 非敏感配置（内存策略等） | 是 |
| `deployment.yaml` | Pod 定义，挂载 ConfigMap `redis-config` | 是 |
| `service.yaml` | 集群内访问入口 | 是 |
| `secret.yaml.example` | Secret 格式参考（可选） | 是 |

**文件 1：** `config/redis.conf`（**只改这一处**，不要又在别处写一遍）

```conf
maxmemory 256mb
maxmemory-policy allkeys-lru
```

**文件 2：** `deployment.yaml`（只含 Deployment，ConfigMap 在部署时用上面的 `redis.conf` 生成）

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: redis
  namespace: mall-middleware
  labels:
    app.kubernetes.io/name: redis
    app.kubernetes.io/part-of: yz-mall
spec:
  replicas: 1
  selector:
    matchLabels:
      app.kubernetes.io/name: redis
  template:
    metadata:
      labels:
        app.kubernetes.io/name: redis
        app.kubernetes.io/part-of: yz-mall
    spec:
      imagePullSecrets:
        - name: acr-gz
      containers:
        - name: redis
          image: registry.cn-guangzhou.aliyuncs.com/devyunze/redis:7.4.5
          imagePullPolicy: IfNotPresent
          command:
            - redis-server
            - /etc/redis/redis.conf
            - --requirepass
            - $(REDIS_PASSWORD)
          env:
            - name: REDIS_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: redis-secret
                  key: requirepass
          ports:
            - containerPort: 6379
          resources:
            requests:
              memory: 128Mi
              cpu: 50m
            limits:
              memory: 640Mi
          volumeMounts:
            - name: redis-config
              mountPath: /etc/redis
      volumes:
        - name: redis-config
          configMap:
            name: redis-config
```

**文件 3：** `service.yaml`

```yaml
apiVersion: v1
kind: Service
metadata:
  name: redis
  namespace: mall-middleware
  labels:
    app.kubernetes.io/name: redis
spec:
  selector:
    app.kubernetes.io/name: redis
  ports:
    - name: redis
      port: 6379
      targetPort: 6379
```

### 4.3 部署命令（按顺序）

在 k3s 节点，进入仓库或把 `apps/mall-middleware/redis/` 拷到节点后：

```bash
cd docs/k3s/apps/mall-middleware/redis

# 1) Secret：密码只在这里填一次（勿提交 Git）
sudo k3s kubectl -n mall-middleware create secret generic redis-secret \
  --from-literal=requirepass='你的Redis密码' \
  --dry-run=client -o yaml | sudo k3s kubectl apply -f -

# 2) ConfigMap：用 config/redis.conf 生成（改配置只改该文件，再重新执行本命令）
sudo k3s kubectl -n mall-middleware create configmap redis-config \
  --from-file=redis.conf=config/redis.conf \
  --dry-run=client -o yaml | sudo k3s kubectl apply -f -

# 3) Deployment
sudo k3s kubectl apply -f deployment.yaml

# 4) Service
sudo k3s kubectl apply -f service.yaml

# 5) 查看状态
sudo k3s kubectl -n mall-middleware get pods,svc -l app.kubernetes.io/name=redis -o wide
```

> **关于密码为何只写步骤 1：** `secret.yaml.example` 只是格式示例；实际部署用 `kubectl create secret`，避免把真密码写进仓库。若你更习惯 YAML，可复制 `secret.yaml.example` 为 `secret.yaml` 改密码后 `kubectl apply -f secret.yaml`（**不要 commit secret.yaml**），二选一即可，不要两处各写一遍。

**期望结果：**

```text
NAME                     READY   STATUS    RESTARTS   AGE
pod/redis-xxxxxx-xxxxx   1/1     Running   0          1m

NAME            TYPE        CLUSTER-IP      PORT(S)
service/redis   ClusterIP   10.43.x.x       6379/TCP
```

### 4.4 改 Nacos，让 Java 服务连上新 Redis

1. 浏览器打开 Nacos 控制台  
2. 进入 namespace：`ff6944dd-b11f-4403-8245-6c621b2f54c8`（与各服务 `bootstrap.yaml` 一致）  
3. 编辑 **`middleware.yaml`**，把 Redis 地址改为：

```yaml
spring:
  data:
    redis:
      host: redis.mall-middleware.svc.cluster.local
      port: 6379
      password: ${redis密码}   # 与 redis-secret 一致
```

4. 发布配置  
5. 重启已运行的 Java Pod（或等 `refresh` 生效，Redis 地址通常需重启）：

```bash
sudo k3s kubectl -n mall rollout restart deploy/mall-sys
```

### 4.5 验证 Redis 是否通

```bash
# 临时起一个调试 Pod
sudo k3s kubectl run -it --rm redis-test --image=registry.cn-guangzhou.aliyuncs.com/devyunze/busybox:1.36.1 --restart=Never -n mall-middleware -- sh

# 在容器里（需安装 redis-cli 或用别的工具；也可在业务 Pod 里测）
# 更简单：看业务日志是否还有 Redis 连接错误
sudo k3s kubectl -n mall logs -l app.kubernetes.io/name=mall-sys --tail=50
```

## 5. 教程 B：部署一个 Spring Cloud 微服务（以 mall-sys 为例）

目标：在 `mall` 命名空间部署 `mall-sys`，端口 **25002**，通过 Nacos 注册，**不对外暴露 NodePort**。

### 5.1 先确认源码里的约定

| 文件 | 路径 | 作用 |
|---|---|---|
| 端口、`spring.application.name` | `mall-admin/mall-sys-startup/src/main/resources/application.yaml` | `server.port: 25002`，`name: mall-sys` |
| Nacos 连接 | `mall-admin/mall-sys-startup/src/main/resources/bootstrap.yaml` | `${NACOS_HOST}:8848`、`${NACOS_PASSWORD}` |
| 扩展配置列表 | 同上 `extension-configs` | `middleware.yaml`、`sa-token.yaml`、`mall-sys.yaml` 等 |

**k3s 里你要做的：** 只保证容器启动时能连上 Nacos；业务配置仍在 Nacos 里改。

### 5.2 构建并推送镜像

在**有 Maven + Docker** 的开发机，仓库根目录 `yz-mall/`：

```bash
# 1) 打包
mvn -pl mall-admin/mall-sys-startup -am -DskipTests package

# 2) 构建镜像（使用 mall-sys-startup 目录下的 Dockerfile）
cd mall-admin/mall-sys-startup
docker build -t registry.cn-guangzhou.aliyuncs.com/devyunze/mall-sys:20260822-1 .
docker push registry.cn-guangzhou.aliyuncs.com/devyunze/mall-sys:20260822-1
```

> tag 建议用日期+序号，不要长期只用 `latest`。

### 5.3 在仓库里写 K8s 清单

**目录：** `docs/k3s/apps/mall/mall-sys/`

**文件 1：** `secret.yaml.example`

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: nacos-secret
  namespace: mall
type: Opaque
stringData:
  password: "Nacos控制台密码"
```

**文件 2：** `deployment.yaml`

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mall-sys
  namespace: mall
  labels:
    app.kubernetes.io/name: mall-sys
    app.kubernetes.io/part-of: yz-mall
spec:
  replicas: 1
  selector:
    matchLabels:
      app.kubernetes.io/name: mall-sys
  template:
    metadata:
      labels:
        app.kubernetes.io/name: mall-sys
        app.kubernetes.io/part-of: yz-mall
    spec:
      imagePullSecrets:
        - name: acr-gz
      containers:
        - name: mall-sys
          image: registry.cn-guangzhou.aliyuncs.com/devyunze/mall-sys:20260822-1
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: 25002
              name: http
          env:
            - name: NACOS_HOST
              value: nacos.mall-middleware.svc.cluster.local
            - name: NACOS_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: nacos-secret
                  key: password
            - name: SPRING_PROFILES_ACTIVE
              value: prod
            - name: TZ
              value: Asia/Shanghai
            - name: JVM_XMS
              value: 512m
            - name: JVM_XMX
              value: 1024m
          resources:
            requests:
              cpu: 100m
              memory: 512Mi
            limits:
              cpu: "1"
              memory: 1Gi
          readinessProbe:
            tcpSocket:
              port: 25002
            initialDelaySeconds: 60
            periodSeconds: 10
            failureThreshold: 6
          livenessProbe:
            tcpSocket:
              port: 25002
            initialDelaySeconds: 120
            periodSeconds: 20
```

**文件 3：** `service.yaml`

```yaml
apiVersion: v1
kind: Service
metadata:
  name: mall-sys
  namespace: mall
  labels:
    app.kubernetes.io/name: mall-sys
spec:
  type: ClusterIP
  selector:
    app.kubernetes.io/name: mall-sys
  ports:
    - name: http
      port: 25002
      targetPort: 25002
```

### 5.4 部署命令（按顺序）

**前置：** Nacos、Redis 已在 k3s 跑起来，且 Nacos 里 `middleware.yaml` 等已发布。

```bash
# 1) Nacos 密码 Secret
sudo k3s kubectl -n mall create secret generic nacos-secret \
  --from-literal=password='你的Nacos密码' \
  --dry-run=client -o yaml | sudo k3s kubectl apply -f -

# 2) 部署
sudo k3s kubectl apply -f docs/k3s/apps/mall/mall-sys/deployment.yaml
sudo k3s kubectl apply -f docs/k3s/apps/mall/mall-sys/service.yaml

# 3) 等待就绪
sudo k3s kubectl -n mall rollout status deploy/mall-sys --timeout=300s
sudo k3s kubectl -n mall get pods,svc -l app.kubernetes.io/name=mall-sys -o wide
```

### 5.5 验证（逐项打勾）

| 步骤 | 命令 / 操作 | 期望 |
|---|---|---|
| Pod 状态 | `kubectl -n mall get pod -l app.kubernetes.io/name=mall-sys` | `1/1 Running` |
| 启动日志 | `kubectl -n mall logs deploy/mall-sys --tail=100` | 无 Nacos 连接失败、无 Redis/MySQL 连不上 |
| Nacos 注册 | Nacos 控制台 → 服务管理 → 服务列表 | 有 `mall-sys`，健康实例 ≥1 |
| 端口 | `kubectl -n mall exec deploy/mall-sys -- sh -c 'wget -qO- http://127.0.0.1:25002/actuator/health 2>/dev/null || echo check-port'` | 能访问或至少进程监听 25002 |

### 5.6 发新版（只改镜像 tag）

```bash
sudo k3s kubectl -n mall set image deploy/mall-sys \
  mall-sys=registry.cn-guangzhou.aliyuncs.com/devyunze/mall-sys:20260822-2

sudo k3s kubectl -n mall rollout status deploy/mall-sys
```

回滚：

```bash
sudo k3s kubectl -n mall rollout undo deploy/mall-sys
```

## 6. 部署 gateway（对外唯一入口）

其他微服务都 `ClusterIP` 后，最后部署 `mall-gateway`，并加 Ingress 或 LoadBalancer。

**目录：** `docs/k3s/apps/mall/mall-gateway/`

**Ingress 示例** `ingress.yaml`（Traefik 为 k3s 默认 Ingress）：

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: mall-gateway
  namespace: mall
spec:
  rules:
    - host: mall.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: mall-gateway
                port:
                  number: 25001
```

```bash
sudo k3s kubectl apply -f docs/k3s/apps/mall/mall-gateway/
sudo k3s kubectl -n mall get ingress
```

浏览器访问 `http://mall.example.com`（需 DNS 或 hosts 指向节点）。

## 7. 推荐启动顺序（整站首次上线）

按依赖关系，**不要跳步**：

```text
1. k3s 节点就绪 + local-path helper 镜像已改 ACR（见《部署RustFS》2.2）
2. 创建命名空间 mall / mall-middleware
3. 创建各命名空间 acr-gz Secret
4. 部署 Nacos（mall-middleware）
5. 部署 Redis（mall-middleware）
6. 在 Nacos 发布 middleware.yaml、sa-token.yaml 等（地址改为 K8s DNS）
7. 部署 mall-sys
8. 部署 mall-pms、mall-oms、mall-tw-* 等
9. 部署 mall-gateway + Ingress
10. 冒烟：登录、列表查询、下单等主链路
```

| 服务 | 模块目录 | 端口 |
|---|---|---|
| mall-gateway | `mall-gateway` | 25001 |
| mall-sys | `mall-admin/mall-sys-startup` | 25002 |
| mall-oms | `mall-oms/mall-oms-startup` | 25003 |
| mall-pms | `mall-pms/mall-pms-startup` | 25004 |
| mall-tw-vehicle | `mall-tw-vehicle/mall-tw-vehicle-startup` | 25005 |
| mall-tw-device | `mall-tw-device/mall-tw-device-startup` | 25006 |

## 8. 新增一个服务时的检查清单（照着勾选）

**仓库侧：**

- [ ] 在 `docs/k3s/apps/<命名空间>/<服务名>/` 建好目录
- [ ] 写好 `deployment.yaml`、`service.yaml`
- [ ] 敏感项用 Secret；`secret.yaml.example` 提交，真实 `secret.yaml` 不提交
- [ ] 镜像 tag 已推到 ACR

**集群侧：**

- [ ] 命名空间存在
- [ ] `acr-gz` Secret 存在
- [ ] `kubectl apply` 成功，Pod `Running` 且 `Ready`
- [ ] 需要 PVC 时 PVC 为 `Bound`

**配置侧：**

- [ ] Nacos 里中间件地址已改为 `*.svc.cluster.local`
- [ ] 服务在 Nacos 注册成功
- [ ] 仅 gateway 对外；其他服务 ClusterIP

## 9. 常见问题（新手最容易卡住的点）

| 现象 | 先查什么 | 处理 |
|---|---|---|
| `ImagePullBackOff` | `kubectl describe pod` Events | 检查镜像名、acr-gz、ACR 是否有该 tag |
| `Pending` + PVC | `kubectl describe pvc` | local-path helper 镜像、磁盘空间 |
| 启动报 Nacos 连不上 | Pod 内 `echo $NACOS_HOST` | Secret 密码、Nacos Service 是否 Running |
| Nacos 有实例但网关 503 | 是否只起了 gateway | 先起 mall-sys 等业务服务 |
| 改了 Nacos 不生效 | Data ID 是否 `refresh: true` | 无 refresh 的项需 `rollout restart` |
| XXL-JOB 执行器离线 | `bootstrap.yaml` 里是否写死 IP | 去掉固定 `xxl.job.executor.ip` |

排障通用顺序见 [常用命令.md](./常用命令.md) 第 11 节。
