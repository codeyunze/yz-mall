# k3s 部署组件与 Spring Cloud 微服务（通用操作）

本文是 **可复用操作手册**：中间件（Redis/Nacos/MQ 等）和 yz-mall Spring Cloud 服务在 k3s 上的统一做法。具体组件参数见专项文档（如 [部署RustFS.md](./部署RustFS.md)、[中间件迁移方案.md](./中间件迁移方案.md)）。

kubectl 在节点上等价于 `sudo k3s kubectl`，命令写法见 [常用命令.md](./常用命令.md)。

## 1. 总体形态

```text
外部请求
  → Traefik Ingress / LoadBalancer
    → mall-gateway（唯一对外业务入口）
      → Nacos 服务发现
        → mall-sys / mall-oms / mall-pms / mall-tw-* ...
          → 中间件 Service DNS
            Redis / Nacos / RocketMQ / MySQL(外部) / RustFS ...
```

| 类别 | 建议命名空间 | 工作负载 | 对外 |
|---|---|---|---|
| 中间件 | `mall-middleware`（RustFS 可继续用独立 `rustfs`） | StatefulSet 或 Deployment + PVC | 仅内网需要时 NodePort/LB；控制台可 Ingress |
| 微服务 | `mall` | Deployment（无状态） | **只暴露 gateway**；其余 ClusterIP |
| 可观测 | `mall-monitor`（可选） | Deployment / DaemonSet | Grafana Ingress；Prometheus 避开宿主机 9090 |

微服务之间 **继续走 Nacos + OpenFeign**，不要改成「每个 Java 服务互相写 K8s Service 名」除非明确废弃 Nacos 发现。中间件地址用 **K8s Service DNS**，写进 Nacos 的 `middleware.yaml`。

## 2. 统一约定

### 2.1 镜像与仓库

- 业务与中间件镜像一律：`registry.cn-guangzhou.aliyuncs.com/devyunze/<name>:<tag>`
- 禁止运行时直拉 Docker Hub；helper / busybox 等也先转存 ACR
- 命名空间内准备拉取凭证（示例名 `acr-gz`），类型 `kubernetes.io/dockerconfigjson`
- 节点 `/etc/rancher/k3s/registries.yaml` 配 ACR 认证；**密码不入库**

### 2.2 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| Deployment / Service | 与 `spring.application.name` 或中间件名一致 | `mall-gateway`、`redis`、`nacos` |
| 配置 | `<name>-config` | `mall-gateway-config` |
| 密钥 | `<name>-secret` | `mall-sys-secret` |
| PVC | `<name>-data` / `<name>-logs` | `redis-data` |
| 标签 | `app.kubernetes.io/name` + `app.kubernetes.io/part-of=yz-mall` | |

### 2.3 配置分层

| 内容 | 放哪 | 说明 |
|---|---|---|
| 非敏感、可公开默认值 | ConfigMap / Nacos | 端口、日志级别、JVM 非密钥项 |
| 密码、Token、数据源口令 | Secret + 环境变量 | 禁止写进 Git / Dashboard 截图 |
| 多服务共享中间件地址 | Nacos `middleware.yaml` | 迁 k3s 后改为 Service DNS |
| 服务专有业务配置 | Nacos `<app>.yaml` | 热更新字段保持 `refresh: true` |

yz-mall 启动模块已用环境变量连 Nacos：

```text
NACOS_HOST          # 例：nacos.mall-middleware.svc.cluster.local
NACOS_PASSWORD      # 来自 Secret
```

`bootstrap.yaml` 中为 `${NACOS_HOST}:8848`。容器里不要再写宿主机局域网 IP。

### 2.4 资源与探针（默认要写）

- 每个容器声明 `resources.requests/limits`（内存必填）
- 有 HTTP 的服务：`readinessProbe` + `livenessProbe`
- Java 可先用 `tcpSocket` 或 `/actuator/health`（需确认已暴露且不被鉴权拦截；网关侧 prometheus 已排除鉴权）
- 有状态组件必须 PVC；`local-path` 为 WaitForFirstConsumer，helper 镜像须能拉取

## 3. 部署中间件（通用步骤）

适用：Redis、Nacos、RocketMQ、Kafka、ES 等。单组件差异只在端口、配置文件、是否 StatefulSet。

### 3.1 检查集群

```bash
kubectl get nodes -o wide
kubectl get sc
kubectl -n kube-system get deploy local-path-provisioner
```

节点 Ready、默认 StorageClass 为 `local-path`。多节点时：有状态服务考虑 `volumeBindingMode` 与数据落在哪台机。

### 3.2 准备镜像

```bash
# 在能访问源仓库的环境（如 GitHub Actions）转存到 ACR 后：
sudo k3s crictl pull registry.cn-guangzhou.aliyuncs.com/devyunze/<镜像>:<tag>
```

### 3.3 命名空间与拉取密钥

```bash
kubectl create namespace mall-middleware --dry-run=client -o yaml | kubectl apply -f -
# 用环境变量创建 docker-registry Secret（示例名 acr-gz），命令见《部署RustFS》
```

### 3.4 配置与密钥

```bash
kubectl -n mall-middleware create configmap <name>-config --from-file=<conf目录> --dry-run=client -o yaml | kubectl apply -f -
kubectl -n mall-middleware create secret generic <name>-secret --from-literal=password="$PASS" --dry-run=client -o yaml | kubectl apply -f -
```

### 3.5 清单结构（模板）

无状态控制台类（Dashboard/UI）：`Deployment` + `Service`。  
有数据目录：`StatefulSet`（或 Deployment + PVC）+ `Service`。

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: <name>
  namespace: mall-middleware
  labels:
    app.kubernetes.io/name: <name>
    app.kubernetes.io/part-of: yz-mall
spec:
  replicas: 1
  selector:
    matchLabels:
      app.kubernetes.io/name: <name>
  template:
    metadata:
      labels:
        app.kubernetes.io/name: <name>
        app.kubernetes.io/part-of: yz-mall
    spec:
      imagePullSecrets:
        - name: acr-gz
      containers:
        - name: <name>
          image: registry.cn-guangzhou.aliyuncs.com/devyunze/<image>:<tag>
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: <port>
          envFrom:
            - configMapRef:
                name: <name>-config
            - secretRef:
                name: <name>-secret
          resources:
            requests:
              memory: 128Mi
              cpu: 50m
            limits:
              memory: 512Mi
          readinessProbe:
            tcpSocket:
              port: <port>
            initialDelaySeconds: 10
            periodSeconds: 10
          volumeMounts:
            - name: data
              mountPath: <data-path>
      volumes:
        - name: data
          persistentVolumeClaim:
            claimName: <name>-data
---
apiVersion: v1
kind: Service
metadata:
  name: <name>
  namespace: mall-middleware
spec:
  selector:
    app.kubernetes.io/name: <name>
  ports:
    - name: main
      port: <port>
      targetPort: <port>
```

集群内访问：`<name>.mall-middleware.svc.cluster.local:<port>`。

### 3.6 落地与验证

```bash
kubectl apply -f <清单.yaml>
kubectl -n mall-middleware get pods,svc,pvc -l app.kubernetes.io/name=<name> -o wide
kubectl -n mall-middleware logs -l app.kubernetes.io/name=<name> --tail=100
kubectl -n mall-middleware describe pod -l app.kubernetes.io/name=<name>
```

期望：Pod Running/Ready，PVC Bound（若有）。再从临时 BusyBox 或业务 Pod 内探测端口。

### 3.7 中间件特别注意

| 组件 | 必须改掉的硬编码 | 说明 |
|---|---|---|
| Redis | requirepass | Secret 注入；应用走 Nacos 连接串 |
| Nacos | 单机/MySQL 地址 | 建议外置 MySQL；`8848/9848/9849` 都要 Service 暴露给 Java 客户端 |
| RocketMQ | namesrv、brokerIP | 用 Service DNS；broker 对外 advertised 地址按多节点规划 |
| Kafka | `ADVERTISED_LISTENERS` | 集群内一套 listener，集群外再单独 listener，禁止写死旧局域网 IP |
| Seata | `SEATA_IP` | 改为 Pod IP 策略或 Service，禁止 compose 里的固定 IP |
| Prometheus | 宿主机 9090 | 与 Kubernetes Dashboard 冲突，换端口或换 Dashboard 端口 |
| node-exporter | 采集宿主机 | 用 DaemonSet，不要当普通 Deployment 只采容器网络 |

有状态组件变更：**先双跑、再改 Nacos 地址、再停旧实例**。

## 4. 部署 Spring Cloud 微服务（通用步骤）

适用：`mall-gateway`、`mall-sys`、`mall-oms`、`mall-pms`、`mall-tw-vehicle`、`mall-tw-device` 等 `*-startup` 模块。

### 4.1 端口与启动模块（现状）

| 服务 | 模块 | 默认端口 |
|---|---|---|
| mall-gateway | `mall-gateway` | 25001 |
| mall-sys | `mall-sys-startup` | 25002 |
| mall-oms | `mall-oms-startup` | 25003 |
| mall-pms | `mall-pms-startup` | 25004 |
| mall-tw-vehicle | `mall-tw-vehicle-startup` | 25005 |
| mall-tw-device | `mall-tw-device-startup` | 25006 |

只打包 **startup / 网关** 的 fat jar 进镜像。分层依赖（interface/dao/core/feign）由 Maven 打进该 jar，不必每个子模块单独部署。

### 4.2 启动顺序

1. 中间件就绪：Nacos、Redis、MySQL（外部）、按需 MQ  
2. Nacos 中已有 `middleware.yaml`、`sa-token.yaml` 及各服务 Data ID  
3. 先 `mall-sys`（认证/权限常被其他服务 Feign）  
4. 再业务域：`mall-pms` / `mall-oms` / `mall-tw-*`  
5. 最后 `mall-gateway` 并配 Ingress  

依赖 Nacos 注册：后启的服务会重试发现，但网关过早对外会 503。

### 4.3 构建镜像

在仓库根目录（版本与模块名按实际）：

```bash
mvn -pl mall-gateway -am -DskipTests package
# 使用仓库根 Dockerfile，ARG APP_MODULE=模块目录名
docker build -f Dockerfile --build-arg APP_MODULE=mall-gateway \
  -t registry.cn-guangzhou.aliyuncs.com/devyunze/mall-gateway:<tag> .
docker push registry.cn-guangzhou.aliyuncs.com/devyunze/mall-gateway:<tag>
```

其他服务把 `APP_MODULE` 换成对应目录（如 `mall-admin/mall-sys-startup` 需按根 Dockerfile 的 `COPY` 规则调整，或为各 startup 使用独立 Dockerfile）。**tag 用 Git SHA 或 `yyyyMMdd-序号`，避免长期只用 `latest`。**

### 4.4 必注入的环境变量

| 变量 | 用途 |
|---|---|
| `NACOS_HOST` | Nacos 主机名（K8s DNS，不含端口） |
| `NACOS_PASSWORD` | Nacos 密码（Secret） |
| `SPRING_PROFILES_ACTIVE` | 如 `prod` |
| `JVM_XMS` / `JVM_XMX` | 与 `resources.limits.memory` 匹配，避免 OOM 被杀 |
| `TZ` | `Asia/Shanghai` |

数据源、Redis、RocketMQ **优先改 Nacos `middleware.yaml`**，不要在每个 Deployment 重复写 JDBC 密码（若必须写，用 Secret）。

XXL-JOB 执行器：`bootstrap` 里若仍有固定 `xxl.job.executor.ip`，上 k3s 后应改为自动探测或去掉，否则调度中心打到旧 IP。

### 4.5 微服务清单要点

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mall-sys
  namespace: mall
spec:
  replicas: 1
  selector:
    matchLabels:
      app.kubernetes.io/name: mall-sys
  template:
    spec:
      imagePullSecrets:
        - name: acr-gz
      containers:
        - name: mall-sys
          image: registry.cn-guangzhou.aliyuncs.com/devyunze/mall-sys:<tag>
          ports:
            - containerPort: 25002
          env:
            - name: NACOS_HOST
              value: nacos.mall-middleware.svc.cluster.local
            - name: NACOS_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: nacos-secret
                  key: password
            - name: TZ
              value: Asia/Shanghai
          resources:
            requests:
              cpu: 100m
              memory: 512Mi
            limits:
              cpu: "1"
              memory: 1Gi
          readinessProbe:
            tcpSocket:
              port: 25002
            initialDelaySeconds: 40
            periodSeconds: 10
          livenessProbe:
            tcpSocket:
              port: 25002
            initialDelaySeconds: 80
            periodSeconds: 20
---
apiVersion: v1
kind: Service
metadata:
  name: mall-sys
  namespace: mall
spec:
  selector:
    app.kubernetes.io/name: mall-sys
  ports:
    - port: 25002
      targetPort: 25002
```

- **replicas**：无状态服务可 >1；必须确认会话在 Sa-Token/Redis，本地 Session 不可水平扩。  
- **Gateway Service**：可 `LoadBalancer` 或仅 ClusterIP + Ingress。  
- 其他 Java 服务：**不要** NodePort 到公网。

### 4.6 网关与 Ingress

集群内用户流量只进 gateway：

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: mall-gateway
  namespace: mall
spec:
  rules:
    - host: mall.example.com   # 按实际域名
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: mall-gateway
                port:
                  number: 25001
```

Nacos 里的网关路由（`gateway.yaml`）仍指向 **Nacos 服务名**（如 `mall-sys`），与 K8s Service 名建议保持一致，避免两套名字。

### 4.7 发布与回滚

```bash
kubectl apply -f mall-sys.yaml
kubectl -n mall rollout status deploy/mall-sys
kubectl -n mall set image deploy/mall-sys mall-sys=registry.cn-guangzhou.aliyuncs.com/devyunze/mall-sys:<new-tag>
kubectl -n mall rollout undo deploy/mall-sys
```

配置只改 Nacos、进程已读取的：对 Dynamic TP 等 `refresh: true` 的项可热更新；改了数据源/`bootstrap` 级项仍需 `rollout restart`。

### 4.8 验证清单

```bash
kubectl -n mall get pods,svc
kubectl -n mall logs -l app.kubernetes.io/name=mall-sys --tail=200
# Nacos 控制台：实例列表是否有 mall-sys / mall-gateway，且为健康
# 经网关：登录、核心只读接口
curl -sS http://<gateway>/actuator/prometheus | head
```

Nacos 有实例但网关 503：查 Feign 超时、目标 Pod 未 Ready、命名空间 ID 是否与 `bootstrap.yaml` 一致。

## 5. 排障顺序（组件与微服务通用）

1. `kubectl get nodes` — 节点压力、磁盘  
2. `kubectl get pods -n <ns> -o wide` — Pending / CrashLoop / ImagePull  
3. `kubectl describe pod` — Events（拉镜像、PVC、探针）  
4. `kubectl logs` / `--previous`  
5. PVC：`describe pvc` + local-path 日志  
6. 中间件连通：从业务 Pod `kubectl exec` 访问 `nacos:8848`、`redis:6379`  
7. Nacos：配置是否发布、发现列表、密码与 namespace  
8. 仍不行：`journalctl -u k3s`、`k3s crictl ps/images`

| 现象 | 常见原因 |
|---|---|
| ImagePullBackOff | 未转 ACR、缺 `imagePullSecrets`、tag 打错 |
| Pending + PVC | local-path helper 镜像拉失败 |
| CrashLoop 启动秒退 | Nacos 地址不通、密码错、JVM 大于 limit |
| Running 但不 Ready | 探针端口/路径错、启动慢未加大 `initialDelaySeconds` |
| Feign 失败 | 对端未注册 Nacos、连错 namespace、只起了网关 |
| 定时任务连不上执行器 | 仍写死宿主机 IP，未改为 Pod 可达地址 |

## 6. 多节点时额外规则

- 中间件与 Java 服务可分节点（污点/容忍或 nodeSelector），避免 ES/Kafka 与业务抢内存  
- 有状态 + `local-path`：Pod 绑在创建卷的那台节点，删节点会丢数据或一直 Pending  
- 对外只从网关节点或统一 Ingress 入口出去  
- 每个节点都要能拉 ACR（`registries.yaml` + 密钥）

## 7. 标准作业检查表

新中间件：

- [ ] ACR 镜像与 tag 已确认  
- [ ] 命名空间、`acr-gz`、ConfigMap/Secret  
- [ ] requests/limits、探针、PVC（若需要）  
- [ ] Service DNS 已写入 Nacos `middleware.yaml`  
- [ ] 控制台是否需要 Ingress（勿默认对公网）

新微服务：

- [ ] fat jar 镜像已推送  
- [ ] `NACOS_HOST` / `NACOS_PASSWORD` 已注入  
- [ ] 仅 gateway 对外  
- [ ] Nacos 注册成功  
- [ ] 探针延迟足够（Java 冷启动）  
- [ ] 无硬编码 IP（XXL-JOB、MQ advertised、Seata）
