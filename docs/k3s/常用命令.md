# k3s 常用命令

说明：以下命令默认在 **k3s 节点本机** 执行。远程管理示例：

```bash
ssh ubuntu@111.223.116.29
```

k3s 自带 kubectl 入口为 `k3s kubectl`。多数场景建议加 `sudo`：

```bash
sudo k3s kubectl get nodes
```

文中统一用 `kubectl` 表示；在节点上等价替换为 `sudo k3s kubectl`。

---

## 1. 服务与版本

### 查看版本

```bash
k3s --version
sudo k3s kubectl version
```

用于确认二进制与 API Server 是否匹配、升级前后对照。

### 服务状态 / 启停 / 重启

```bash
sudo systemctl status k3s
sudo systemctl start k3s
sudo systemctl stop k3s
sudo systemctl restart k3s
sudo systemctl enable k3s
```

- `status`：看是否 active、最近启动失败原因。
- `restart`：节点短暂不可用；业务 Pod 会重建，非必要勿频繁操作。
- `enable`：开机自启。

### 服务日志（systemd）

```bash
sudo journalctl -u k3s -f
sudo journalctl -u k3s --since "1 hour ago"
```

节点 NotReady、API Server 起不来时优先看这里。

## 2. kubeconfig（本机 kubectl）

节点上默认配置文件：

```text
/etc/rancher/k3s/k3s.yaml
```

### 在服务器上给当前用户用

```bash
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown "$USER:$USER" ~/.kube/config
chmod 600 ~/.kube/config
# 若从外网连本机 API，把 server 地址从 127.0.0.1 改成实际可达 IP
```

之后可直接：

```bash
kubectl get nodes
```

### 拷到开发机（慎用）

```bash
scp ubuntu@111.223.116.29:/etc/rancher/k3s/k3s.yaml ./k3s.yaml
# 修改其中 server: https://127.0.0.1:6443 为 https://<公网或内网IP>:6443
# 并确保 6443 防火墙/安全组已按需开放
export KUBECONFIG=./k3s.yaml
```

> kubeconfig 含集群管理员凭证，勿提交 Git，勿发到公开渠道。

## 3. 集群巡检

### 节点

```bash
kubectl get nodes -o wide
kubectl describe node <节点名>
kubectl top node          # 需 metrics-server 正常
```

关注：`STATUS=Ready`、磁盘/内存压力、`Taints`、`Conditions`。

### 命名空间与总览

```bash
kubectl get ns
kubectl get all -A
kubectl get pods -A -o wide
kubectl get svc -A
kubectl get ingress -A
```

- `-A` / `--all-namespaces`：全命名空间。
- `-o wide`：多显示节点 IP、Pod IP 等。

### 事件（排障首选）

```bash
kubectl get events -A --sort-by='.lastTimestamp'
kubectl get events -n <命名空间> --sort-by='.lastTimestamp'
```

Pending / CrashLoopBackOff 时，事件里常有 ImagePull、Volume、资源不足等原因。

## 4. 工作负载（Deployment / Pod）

### 查询

```bash
kubectl get deploy,sts,ds,pod -n <命名空间> -o wide
kubectl get pod -n <命名空间> -l app=<标签>
kubectl describe pod <pod名> -n <命名空间>
```

`describe` 底部 **Events** 最有用。

### 日志

```bash
kubectl logs <pod名> -n <命名空间>
kubectl logs <pod名> -n <命名空间> -c <容器名>   # 多容器时指定
kubectl logs <pod名> -n <命名空间> --tail=200 -f
kubectl logs <pod名> -n <命名空间> --previous     # 看上一次崩溃容器日志
```

### 进入容器

```bash
kubectl exec -it <pod名> -n <命名空间> -- sh
# 镜像只有 bash 时：
kubectl exec -it <pod名> -n <命名空间> -- bash
```

### 扩缩容 / 重启

```bash
kubectl scale deploy/<名称> --replicas=2 -n <命名空间>
kubectl rollout restart deploy/<名称> -n <命名空间>
kubectl rollout status deploy/<名称> -n <命名空间>
kubectl rollout history deploy/<名称> -n <命名空间>
kubectl rollout undo deploy/<名称> -n <命名空间>
```

- `rollout restart`：滚动重建，常用于改了 Secret/ConfigMap 后刷新环境变量。
- `undo`：回滚到上一版本（需有 revision 历史）。

### 删除 Pod（触发重建）

```bash
kubectl delete pod <pod名> -n <命名空间>
# 卡住删不掉时（慎用）：
kubectl delete pod <pod名> -n <命名空间> --force --grace-period=0
```

由 Deployment 管理的 Pod 删除后会自动再创建。

## 5. 配置与密钥

```bash
kubectl get cm,secret -n <命名空间>
kubectl describe cm <名称> -n <命名空间>
kubectl get cm <名称> -n <命名空间> -o yaml
kubectl get secret <名称> -n <命名空间> -o yaml
# 解码 Secret 某字段（示例）：
kubectl get secret <名称> -n <命名空间> -o jsonpath='{.data.<键>}' | base64 -d; echo
```

应用配置变更后，通常还需要 `rollout restart` 相关 Deployment。

## 6. 服务与网络

```bash
kubectl get svc -n <命名空间> -o wide
kubectl describe svc <名称> -n <命名空间>
kubectl get endpoints -n <命名空间>
```

### 类型说明（本环境常见）

| Service 类型 | 说明 |
|---|---|
| ClusterIP | 仅集群内访问 |
| NodePort | 节点端口映射 |
| LoadBalancer | 本环境由 **svclb** 占节点端口；EXTERNAL-IP 常为节点内网 IP |

### 临时端口转发（调试）

```bash
kubectl port-forward -n <命名空间> svc/<服务名> 9000:9000
# 本机浏览器/客户端访问 127.0.0.1:9000
```

### Traefik / Ingress

```bash
kubectl get ingress -A
kubectl describe ingress <名称> -n <命名空间>
kubectl -n kube-system get deploy,pod,svc | grep -i traefik
```

## 7. 存储（PV / PVC / StorageClass）

本环境默认 StorageClass：`local-path`，绑定模式多为 **WaitForFirstConsumer**（要等 Pod 调度到节点后才真正建卷）。

```bash
kubectl get sc
kubectl get pv
kubectl get pvc -A
kubectl describe pvc <名称> -n <命名空间>
```

常见 Pending 原因：

1. PVC 未绑定（看 `describe pvc` / Pod Events 的 VolumeBinding）。
2. 节点磁盘空间不足或 local-path 目录权限问题。
3. 存储类名写错、或没有默认 SC。

查看 local-path 数据目录（节点本机）：

```bash
sudo ls -la /var/lib/rancher/k3s/storage/
```

## 8. 应用 YAML / Helm

### 声明式部署

```bash
kubectl apply -f app.yaml
kubectl apply -f ./manifests/
kubectl delete -f app.yaml
kubectl diff -f app.yaml          # 与集群现状对比（需权限）
```

### 导出当前对象（备份参考）

```bash
kubectl get deploy <名称> -n <命名空间> -o yaml > deploy-backup.yaml
kubectl get all,cm,secret,pvc,ingress -n <命名空间> -o yaml > ns-backup.yaml
```

导出含 Secret，注意脱敏与保管。

### Helm（若节点已安装 helm）

k3s 也可通过 Job 方式装 Chart（本集群可见 `helm-install-*` Completed Job）。有 helm 客户端时：

```bash
helm list -A
helm status <release> -n <命名空间>
helm upgrade --install <release> <chart> -n <命名空间> -f values.yaml
helm rollback <release> <revision> -n <命名空间>
helm uninstall <release> -n <命名空间>
```

## 9. 容器运行时（containerd / crictl）

k3s 使用内嵌 containerd，可用：

```bash
sudo k3s crictl ps
sudo k3s crictl pods
sudo k3s crictl images
sudo k3s crictl logs <容器ID>
sudo k3s crictl inspect <容器ID>
```

适合：kubectl 层异常、排查镜像是否已拉取、runtime 级日志。

### 镜像相关

```bash
# 看 Pod 拉取失败原因
kubectl describe pod <pod名> -n <命名空间>
# 预拉取（示例：ctr）
sudo k3s ctr images ls
sudo k3s ctr images pull <镜像地址>
```

私有仓库需在节点配置 registry mirror / auth（`/etc/rancher/k3s/registries.yaml`），改完后重启 k3s。

## 10. 资源与配额快速看

```bash
kubectl top node
kubectl top pod -A
kubectl top pod -n <命名空间>
free -h
df -h
```

单节点小规格机器上，Pending 也可能是 CPU/Memory 请求过大；用 `describe pod` 看 FailedScheduling。

## 11. 常用排障路径（建议顺序）

1. `kubectl get nodes` → 节点是否 Ready  
2. `kubectl get pods -A` → 找非 Running / 非 Completed  
3. `kubectl describe pod ...` → Events  
4. `kubectl logs ...` / `--previous`  
5. `kubectl get events -n ...`  
6. 存储问题再查 `pvc` / `pv` / `sc`  
7. 仍不行：`journalctl -u k3s`、`k3s crictl ps`

### 状态速查

| 状态 | 常见含义 |
|---|---|
| Pending | 调度不到节点，或等卷绑定 / 资源不足 |
| ContainerCreating | 拉镜像、挂卷、创建容器中 |
| ImagePullBackOff | 镜像名/仓库认证/网络问题 |
| CrashLoopBackOff | 进程反复退出，看日志 |
| Completed | Job 正常结束（不必当故障） |
| Error | Job/Pod 失败 |

## 13. 危险操作清单（慎用）

```bash
# 卸载整个 k3s（会清空本机集群数据，不可随便执行）
# /usr/local/bin/k3s-uninstall.sh

kubectl delete ns <命名空间>                 # 删命名空间下几乎所有资源
kubectl delete pvc --all -n <命名空间>       # 数据卷声明删除后，按回收策略可能丢数据
kubectl drain <节点> --ignore-daemonsets     # 驱逐节点上的 Pod
```

执行前确认环境与备份；生产操作建议双人复核。
