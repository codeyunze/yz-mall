
# 商城系统设计方案

## 一、项目概述

### 1.1 项目定位
- **类型**：B2C 自营商城（预留多商户扩展）
- **用户量级**：预期 100 万用户
- **商品类型**：实物商品 + 虚拟商品
- **C端接入**：微信小程序（基于 uni-app，后续可快速扩展 H5、APP）
- **B端接入**：PC Web 管理后台（平台管理 + 商家管理，统一入口，RBAC 区分）

### 1.2 部署与容灾
- **部署方式**：私有化部署
- **容灾要求**：两地容灾，一机房异常时另一机房可临时接管，RTO < 30 分钟
- **基础设施**：Docker + Kubernetes 集群，跨机房编排

## 二、系统架构设计

### 2.1 技术栈全景

| 层次 | 技术选型 | 版本/说明 |
|------|---------|-----------|
| **C端前端** | uni-app (Vue3) | 微信小程序优先，跨端复用 |
| **B端前端** | Vue3 + Vite + Element Plus | PC 管理后台 |
| **后端框架** | Spring Cloud Alibaba + Spring Boot | 2022.x + 3.x |
| **注册/配置中心** | Nacos | 服务发现 + 配置管理，跨机房集群部署 |
| **API 网关** | Spring Cloud Gateway | 统一鉴权、路由、限流 |
| **服务调用** | OpenFeign + Nacos | 声明式 HTTP + 高性能 RPC |
| **认证鉴权** | Sa-Token | 轻量权限认证，支持微服务分布式会话 |
| **分布式事务** | Seata | AT 模式，解决订单-库存-余额数据一致性 |
| **定时任务** | XXL-JOB | 分布式任务调度 |
| **关系型数据库** | MySQL 8.0 + ShardingSphere-Proxy | 主从复制 + 分库分表预留 |
| **缓存** | Redis Cluster | 令牌存储、购物车、热点数据，跨机房哨兵 |
| **搜索引擎** | Elasticsearch | 商品搜索（一期可降级 MySQL，二期接入） |
| **文档数据库** | MongoDB | 操作日志、系统日志（结构多变、写入量大） |
| **对象存储** | 腾讯云COS | 私有化图片/文件存储 |
| **物流对接** | 快递鸟 / 快递100 SDK | 物流轨迹查询 |
| **CI/CD** | Jenkins + Docker + K8s | 自动化构建部署 |

### 2.2 认证鉴权方案（Sa-Token）

- **登录流程**：C端微信授权静默登录 → 获取 openid → 绑定手机号 → Sa-Token 颁发令牌
- **B端登录**：账号密码登录 → Sa-Token 颁发令牌，绑定角色权限
- **网关鉴权**：全局过滤器校验 Sa-Token 令牌有效性，从 Redis 读取会话
- **微服务鉴权**：通过 `StpUtil` 获取登录用户，注解 `@SaCheckPermission` 控制权限
- **令牌存储**：Redis Cluster，跨机房共享会话，容灾切换不影响用户登录态
- **权限模型**：RBAC（用户 → 角色 → 菜单/按钮权限），支持数据权限（商家仅看本店数据）

### 2.3 微服务模块划分

| 模块 | 职责 | 一期实现 | 二期规划 |
|------|------|:---:|:---:|
| **gateway** | API 网关，统一鉴权、限流、路由 | ✅ | - |
| **auth-center** | 登录认证，令牌管理 | ✅ | - |
| **user-service** | C 端用户信息、收货地址 | ✅ | - |
| **merchant-service** | 商家管理、店铺管理 | ✅（手动创建） | ✅（入驻审核流） |
| **product-service** | 商品 SPU/SKU、类目、品牌、库存 | ✅ | - |
| **order-service** | 订单、购物车、交易流水 | ✅ | - |
| **payment-service** | 余额账户、支付流水 | ✅（仅余额） | ✅（第三方支付） |
| **logistics-service** | 发货、物流轨迹查询 | ✅ | 电子面单 |
| **marketing-service** | 优惠券、营销活动 | ❌ | ✅ |
| **search-service** | 商品搜索，同步 ES | ❌ | ✅ |
| **system-service** | RBAC 权限、数据字典、操作日志 | ✅ | - |

### 2.4 两地容灾架构

```
┌─────────────────────────────────────────────────────────────┐
│                        DNS 流量调度                           │
└────────────┬──────────────────────────────┬─────────────────┘
             │                              │
    ┌────────▼─────────┐          ┌────────▼─────────┐
    │    机房 A (主)    │  专线    │    机房 B (备)    │
    │                  │◄────────►│                  │
    │ Nacos Cluster    │          │ Nacos Cluster    │
    │ Gateway Cluster  │          │ Gateway Cluster  │
    │ 微服务 Pod       │          │ 微服务 Pod       │
    │ MySQL 主库       │  异步复制 │ MySQL 从库       │
    │ Redis Cluster    │◄──Gossip─►│ Redis Cluster    │
    │ ES / MongoDB     │          │ ES / MongoDB     │
    │ MinIO            │  数据同步 │ MinIO            │
    └──────────────────┘          └──────────────────┘
```

- MySQL 跨机房主从异步复制，备机房切换时手动/自动提升为可写
- Redis Cluster 跨机房哨兵监控，共享令牌可无缝切换
- Nacos 跨机房集群保证注册中心高可用
- 故障切换：DNS 流量调度到存活机房，网关自动路由到健康服务

## 三、功能模块概要设计

### 3.1 版本规划总览

| 版本 | 目标 | 核心功能 |
|------|------|---------|
| **V1.0（一期）** | 快速上线可用的闭环系统 | 用户购物全链路 + 基础管理后台 |
| **V2.0（二期）** | 完善运营能力 | 商家入驻审核、营销工具、ES 搜索、财务管理 |

### 3.2 C端功能（微信小程序 · V1.0）

#### 3.2.1 用户模块
- **微信授权登录**：静默获取 openid，引导绑定手机号
- **个人中心**：查看/修改头像、昵称
- **地址管理**：新增、修改、删除收货地址，支持设为默认地址

#### 3.2.2 商品浏览
- **商品分类**：按类目树展示，支持多级分类
- **商品列表**：按类目筛选，支持关键词搜索（一期 MySQL LIKE）
- **商品详情**：商品主图、轮播图、规格选择（SKU）、库存显示、商品描述

#### 3.2.3 购物车
- 加入购物车、修改数量、删除商品
- 勾选商品进入结算（一期按单品库存校验）
- 购物车数据存储 Redis，登录后同步

#### 3.2.4 下单与支付
- **下单流程**：选择收货地址 → 确认订单 → 锁定库存 → 余额扣减 → 生成订单
- **仅支持余额支付**，支付需验证支付密码（可配置开关）
- **虚拟商品**：支付后自动发货（卡密/激活码直接展示），订单状态直接变已完成
- **取消订单**：未支付订单超时自动取消（XXL-JOB 定时扫描），退还库存
- **订单状态流转**：

```
待付款 ──支付──► 待发货 ──发货──► 待收货 ──确认──► 已完成
  │                │                │
  └──取消──► 已取消  └──退款申请──► 退款中 ──审核──► 已退款
```

#### 3.2.5 订单管理
- 订单列表按状态分 Tab：全部/待付款/待发货/待收货/已完成/已取消
- 订单详情：商品信息、物流单号、状态跟踪
- **确认收货**：用户点击确认收货，订单状态变更为已完成

#### 3.2.6 售后（简化版）
- **仅退款**：已支付未发货的订单可申请退款
- 提交退款原因 → 商家审核 → 通过后退还余额

#### 3.2.7 物流查询
- 订单详情页查看物流轨迹（调用第三方物流 SDK）
- 发货时由商家录入快递单号

### 3.3 B端功能（管理后台 · V1.0）

> B端为 PC Web 单页应用，统一入口登录，根据角色 RBAC 展示不同菜单。

#### 3.3.1 平台管理端

| 功能模块 | 说明 |
|---------|------|
| **管理员登录** | 平台管理员账号密码登录，Sa-Token 认证 |
| **角色与权限管理** | 创建角色 → 分配菜单/按钮权限 → 绑定管理员 |
| **商家管理（简化）** | 手动创建商家账号、店铺信息（二期改为入驻审核流程） |
| **类目管理** | 维护商品类目树，配置类目属性（规格/参数） |
| **数据字典** | 维护系统枚举值（订单状态、商品类型等） |
| **操作日志** | 管理员操作记录存入 MongoDB，支持按人、时间、模块查询 |

#### 3.3.2 商家管理端

| 功能模块 | 说明 |
|---------|------|
| **商品管理** | 发布商品（实物/虚拟）、编辑、上下架、库存管理、卡密导入（虚拟商品） |
| **订单管理** | 查看本店订单列表、订单详情、发货操作（录入物流单号） |
| **售后管理** | 查看退款申请，审核通过/拒绝 |
| **物流查询** | 查看已发货订单的物流轨迹 |

### 3.4 二期功能规划（V2.0）

## 四、关键设计决策

### 4.1 多商户扩展预留

- 核心业务表（商品、订单、购物车、支付流水）统一预留 `merchant_id` 字段
- 一期所有数据挂靠在默认自营商户下
- 二期开放商家入驻后，按 `merchant_id` 进行数据隔离
- 商家端查询自动注入 `merchant_id` 条件，确保数据安全

### 4.2 支付扩展预留

- `payment-service` 定义支付渠道抽象接口 `PaymentChannel`
- 一期实现 `BalancePaymentChannel`（余额支付）
- 二期新增微信支付、支付宝支付只需实现接口并注册即可
- 支付流水表预留 `channel`（支付渠道）和 `channel_order_no`（渠道订单号）字段

### 4.3 权限体系设计

- 采用 RBAC 模型：用户 → 角色 → 权限（菜单 + 按钮）
- 平台管理员角色：全部菜单权限
- 商家管理员角色：仅商家端菜单 + 本店数据权限
- 权限注解：`@SaCheckPermission("order:ship")` 控制按钮级权限
- 数据权限：通过 AOP 切面自动为商家端查询注入 `merchant_id` 过滤条件
