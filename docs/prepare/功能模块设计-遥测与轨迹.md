## 1. 功能实现目标

### 1.1 目标说明

作为新能源车企车联网侧的**位置与轨迹数据平面**，消费车机经 EMQX → Kafka 上报的高频 GPS（及可选信号），维护每车最新位置，落库可查询轨迹，并向前端提供地图展示所需 API。本模块是 Demo「地图上能动」的关键路径。

| 编号 | 目标 | 验收要点 |
|------|------|----------|
| G1 | 消费原始遥测 | 消费 Kafka `tw-telemetry-raw`（Key=VIN），解析 JSON，校验经纬度合法 |
| G2 | 最新位置 | 写 Redis `tw:gps:latest:{vin}` + 表 `tw_gps_latest`（UPSERT） |
| G3 | 轨迹落库 | 写入轨迹明细（P0 单表限量或按月分表二选一，推荐按月分表骨架） |
| G4 | 最新位置查询 | 按 VIN / vehicleId 查最新点（优先 Redis，回源 DB） |
| G5 | 轨迹查询 | 按 VIN + 时间范围返回点序列；限制时间窗与点数，防大查询 |
| G6 | 地图展示支撑 | 返回前端折线可用的坐标数组；坐标系约定 WGS84（或文档标明 GCJ02 转换责任在前端） |
| G7 | 简单去噪（P0 轻量） | 过滤非法坐标、可选速度跳变粗过滤 |
| G8 | 信号/电量（P1） | 扩展字段或独立消息写入 latest；监控页展示 |

### 1.2 非目标（本模块不做）

- EMQX 桥接、Kafka 生产（`tw-access`）
- 车辆/终端/指令主数据（`tw-vehicle` / `tw-device` / `tw-command`）
- 在线状态写入（`tw-access`）；查询可只读 `tw:online:{vin}` 一并返回
- 电子围栏判定（`tw-alarm` 二期）
- 时序库 InfluxDB / TDengine 生产选型（验证阶段 MySQL + Redis 即可）

### 1.3 服务与分层归属

| 项 | 约定 |
|----|------|
| 服务名 | `tw-telemetry`（建议端口 `30104`） |
| 分层 | `interface` / `dao` / `core` / `feign` / `startup` |
| 包名 | `com.yz.mall.tw.telemetry` |
| 类前缀 | `TwGps` / `TwTelemetry` |
| 统一响应 | `Result` / `ResultTable` + `ApiController` |
| 鉴权 | Gateway + `@SaCheckPermission("api:tw:telemetry:*")`；数据范围调 `tw-vehicle` `access/check` |

### 1.4 与上下游关系

```mermaid
flowchart LR
  Car["车机"] -->|MQTT up/gps| EMQX
  EMQX --> Acc["tw-access"]
  Acc -->|Kafka tw-telemetry-raw| K[(Kafka)]
  K --> T["tw-telemetry"]
  T --> Redis[(tw:gps:latest)]
  T --> DB[(tw_gps_latest / tw_gps_track_*)]
  PC["管理端地图"] --> GW["gateway"]
  GW --> T
  T -->|access/check| V["tw-vehicle"]
```

| 能力 | 负责方 |
|------|--------|
| GPS 上行桥接到 Kafka | `tw-access` |
| 消费、清洗、落库、查询 API | `tw-telemetry` |
| 车辆访问权限（车主/授权 scope 含位置位 `2`） | `tw-vehicle` Extend |
| 在线状态 | `tw-access` 写 Redis；本模块只读 |

## 2. 涉及角色与权限范围

### 2.1 角色定义

| 角色编码 | 角色名称 | 说明 |
|----------|----------|------|
| `SUPER_ADMIN` | 平台管理员 | 全部查询 |
| `TW_OPERATOR` | 运营人员 | 监控与轨迹查询（全量车辆） |
| `TW_MONITOR` | 只读监控 | 仅查位置/轨迹，无写操作（本模块本无写管理接口） |
| `TW_OWNER` | 车主 | 仅名下车辆；需 `auth_scope` 含位置位或车主默认具备 |
| `TW_AUTH_USER` | 授权用户 | 仅被授权车辆且 `auth_scope` 含 `2` |

### 2.2 功能点 × 角色权限矩阵

| 功能点 | 权限码（建议） | 管理员 | 运营 | 只读监控 | 车主 | 授权用户 |
|--------|----------------|:------:|:----:|:--------:|:----:|:--------:|
| 最新位置 | `api:tw:telemetry:latest` | ✅ | ✅ | ✅ | ✅（己车） | ✅（scope≥2） |
| 轨迹查询 | `api:tw:telemetry:track` | ✅ | ✅ | ✅ | ✅（己车） | ✅（scope≥2） |
| 批量最新位置（监控大屏） | `api:tw:telemetry:latest:batch` | ✅ | ✅ | ✅ | ❌ | ❌ |

### 2.3 数据权限

查询前调用 `GET /extend/tw/vehicle/access/check`，所需 scope=`2`（查看位置/轨迹）。运营/管理员跳过绑定校验（全量）。

### 2.4 菜单建议

```
Titan Watch
├── 实时监控（最新位置 / 在线，地图点）
└── 轨迹查询（VIN + 时间范围 + 折线）
```

## 3. 数据表设计

### 3.1 设计说明

- **热数据** `tw_gps_latest`：每 VIN 一行，UPSERT；与 Redis 双写。
- **冷数据** `tw_gps_track_yyyyMM`：按月分表；P0 若求快可先单表 `tw_gps_track` + 定时清理近 N 天。
- 字段：`create_id`/`update_id` 对 latest 意义较弱（系统写入），轨迹明细以设备上报为主，`create_id` 可空。
- Kafka Topic：`tw-telemetry-raw`（Key=VIN）。

### 3.2 表：`tw_gps_latest`（最新位置）

```sql
CREATE TABLE `tw_gps_latest` (
  `id` bigint NOT NULL COMMENT '主键标识',
  `vin` varchar(32) NOT NULL COMMENT '车架号VIN',
  `vehicle_id` bigint DEFAULT NULL COMMENT '车辆ID冗余，可空',
  `lng` decimal(10,7) NOT NULL COMMENT '经度',
  `lat` decimal(10,7) NOT NULL COMMENT '纬度',
  `altitude` decimal(10,2) DEFAULT NULL COMMENT '海拔米',
  `speed` decimal(8,2) DEFAULT NULL COMMENT '速度km/h',
  `heading` decimal(6,2) DEFAULT NULL COMMENT '航向角0-360',
  `gps_time` datetime NOT NULL COMMENT 'GPS定位时间（车机侧）',
  `receive_time` datetime NOT NULL COMMENT '云端接收时间',
  `soc` decimal(5,2) DEFAULT NULL COMMENT '电池SOC百分比（P1）',
  `signal_level` tinyint DEFAULT NULL COMMENT '信号强度等级（P1）',
  `raw_ext` json DEFAULT NULL COMMENT '扩展字段JSON',
  `create_id` bigint DEFAULT NULL COMMENT '创建人用户ID',
  `update_id` bigint DEFAULT NULL COMMENT '更新人用户ID',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `invalid` bigint NOT NULL DEFAULT 0 COMMENT '数据是否有效：0数据有效',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_vin` (`vin`),
  KEY `idx_gps_time` (`gps_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='车辆最新GPS位置';
```

### 3.3 表：`tw_gps_track` / `tw_gps_track_yyyyMM`（轨迹明细）

**P0 推荐**：物理表按月 `tw_gps_track_202608`，应用层路由；或先单表：

```sql
CREATE TABLE `tw_gps_track` (
  `id` bigint NOT NULL COMMENT '主键标识',
  `vin` varchar(32) NOT NULL COMMENT '车架号VIN',
  `vehicle_id` bigint DEFAULT NULL COMMENT '车辆ID冗余',
  `lng` decimal(10,7) NOT NULL COMMENT '经度',
  `lat` decimal(10,7) NOT NULL COMMENT '纬度',
  `altitude` decimal(10,2) DEFAULT NULL COMMENT '海拔米',
  `speed` decimal(8,2) DEFAULT NULL COMMENT '速度km/h',
  `heading` decimal(6,2) DEFAULT NULL COMMENT '航向角',
  `gps_time` datetime NOT NULL COMMENT 'GPS定位时间',
  `receive_time` datetime NOT NULL COMMENT '云端接收时间',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `invalid` bigint NOT NULL DEFAULT 0 COMMENT '数据是否有效：0数据有效',
  PRIMARY KEY (`id`),
  KEY `idx_vin_gpstime` (`vin`, `gps_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='车辆GPS轨迹明细';
```

**索引**：`(vin, gps_time)` 支撑轨迹区间查询。  
**保留策略**：P0 演示保留 7～30 天；P1 增加 XXL-JOB 清理。

### 3.4 Kafka 消息体约定（上行 GPS）

```json
{
  "vin": "LXXXXXXXXXXXXXXX",
  "lng": 113.264385,
  "lat": 23.129112,
  "speed": 36.5,
  "heading": 90.0,
  "altitude": 12.0,
  "gpsTime": "2026-08-04T15:00:01.000+08:00",
  "soc": 78.5,
  "signalLevel": 4
}
```

Topic：`tw-telemetry-raw`；Key：`vin`；消费组：`tw-telemetry-gps`。

### 3.5 Redis 快照

Key：`tw:gps:latest:{vin}`  
Value：与 latest 表核心字段一致的 JSON；TTL 可不设或 7 天滑动续期。

## 4. 接口设计

> 前缀：`/tw/telemetry/**`

### 4.1 最新位置

- `GET /tw/telemetry/latest?vin=` 或 `?vehicleId=`
- 权限：`api:tw:telemetry:latest`

**出参** `TwGpsLatestVo`：`vin`、`lng`、`lat`、`speed`、`heading`、`gpsTime`、`receiveTime`、`online`（可选读 online）、`soc`/`signalLevel`（P1）。

### 4.2 批量最新位置（监控）

- `POST /tw/telemetry/latest/batch`
- 入参：`vins[]` 或空=运营可见范围内分页车辆（建议限制 ≤200）
- 出参：`List<TwGpsLatestVo>`

### 4.3 轨迹查询

- `POST /tw/telemetry/track`
- 权限：`api:tw:telemetry:track`

**入参** `TwGpsTrackQueryDto`：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `vin` / `vehicleId` | — | 是 | 二选一 |
| `startTime` | datetime | 是 | 开始（含） |
| `endTime` | datetime | 是 | 结束（含） |
| `maxPoints` | int | 否 | 默认 2000，上限 5000；超限抽稀 |

**约束**：`endTime - startTime` ≤ 24h（P0 可配置，防扫全表）。

**出参** `TwGpsTrackVo`：

| 字段 | 说明 |
|------|------|
| `vin` | VIN |
| `points[]` | `{lng,lat,speed,heading,gpsTime}` 按时间升序 |
| `total` | 原始命中点数（抽稀前） |
| `sampled` | 是否已抽稀 |

### 4.4 Extend（供 vehicle 详情聚合）

| 接口 | 说明 |
|------|------|
| `GET /extend/tw/telemetry/latest/{vin}` | 车辆详情位置摘要 |

## 5. 核心流程

### 5.1 上报消费

```mermaid
sequenceDiagram
  participant Car as 车机
  participant Acc as tw-access
  participant K as Kafka
  participant T as tw-telemetry
  participant R as Redis
  participant DB as MySQL

  Car->>Acc: MQTT up/gps
  Acc->>K: tw-telemetry-raw
  K->>T: poll
  T->>T: 解析校验去噪
  T->>R: SET tw:gps:latest:{vin}
  T->>DB: UPSERT tw_gps_latest
  T->>DB: INSERT tw_gps_track*
```

### 5.2 轨迹查询

```mermaid
sequenceDiagram
  participant PC as 管理端
  participant T as tw-telemetry
  participant V as tw-vehicle
  participant DB as MySQL

  PC->>T: POST /track
  T->>V: access/check scope=2
  V-->>T: allowed
  T->>DB: SELECT by vin + time
  T->>T: 抽稀
  T-->>PC: points
```

## 6. 异常与业务码建议

| 场景 | 提示 |
|------|------|
| VIN 无权限 | 无权查看该车辆位置 |
| 时间窗过大 | 查询时间范围不能超过 N 小时 |
| 无轨迹数据 | 返回空 points，非错误 |
| 非法坐标消息 | 消费侧丢弃并打 warn（不计业务失败） |
| Kafka 积压 | 运维扩容/加分区（面试点） |

---

## 7. 实现要点

| 项 | 约定 |
|----|------|
| 幂等消费 | 同点可重复写 latest；轨迹可接受少量重复（或用 vin+gpsTime 唯一，冲突忽略） |
| 抽稀 | 等距取样或按 maxPoints 均匀抽样 |
| 坐标系 | 存储 WGS84；若地图用高德，前端做 GCJ02 转换 |
| 上报频率 | 模拟器 1～5s/点；云端可限流丢中间点（可选） |
